# Android client

The pre-release native client uses a shared Rust transport and state layer, generated bindings, and Compose. Cloud execution is owned by the server. Credentials, drafts, and per-entry transcript caches are encrypted with a device-keystore key and excluded from backup. A public device-authentication service and installable signed release have not yet been delivered.

## Build

Use a JDK compatible with the pinned build plugin. Run `scripts/android-setup.sh` from the repository root to install the verified command-line tools, SDK, native compiler, and emulator into a user-owned directory. Review and accept the SDK terms when requested. Set `ANDROID_SDK_ROOT` to use another existing installation; no shell configuration is rewritten.

Run `apps/android/gradlew -p apps/android :app:assembleDebug`. Native bindings and shared libraries are generated by the build. Debug builds use the native development profile; `GESANG_NATIVE_PROFILE` can select another debug profile. Release builds always compile the native library with release optimization. Set `GESANG_ANDROID_ABIS` to the space-separated subset needed by a connected device or emulator.

For the default task-owned SDK location, supply `ANDROID_HOME="${XDG_DATA_HOME:-$HOME/.local/share}/gesang/android-sdk"` to Gradle. The setup script does not modify your shell configuration. Source formatting uses `scripts/android-format.sh --check`, which verifies and runs the pinned ktfmt artifact with Kotlin language style.

The current build targets the 64-bit ARM and x86 ABIs on Android 7.0 (API 24) or later, as required by the current messaging library. The application package is `dev.gesang.app`, and its browser-authorization callback is `dev.gesang.app:/oauth/callback`. Configure the deployment's public native OAuth client with that exact callback, the configured audience, and proof-key support. No client secret belongs in this application.

Production connections require HTTPS. A debug build can use explicit loopback development endpoints; this exception does not allow arbitrary cleartext network hosts. Pairing with a server does not grant task authority: the user must explicitly select a permission mode.

## Notifications

For a deployment-owned messaging project, place its public application configuration at `app/google-services.json` before building. Use matching server-side sender credentials. The current Firebase SDK registers Firebase Installation IDs; the platform target is typed explicitly, and a server acknowledgment is separate from delivery. Without that configuration, remote notifications remain unavailable. Send data-only locators, never a conversation or task title; the app provides localized generic text and checks the active agent before displaying it. Server device-session revocation and live delivery still need end-to-end verification.

## Verification

Capture interface evidence from an emulator or device, including both themes, large fonts, keyboard, system back, disconnected state, and a real server connection. Browser design captures are references and do not constitute native verification. Release performance and accessibility remain unverified until the corresponding native runs are recorded.

Device tests cover the actual packaged Rust library, Keystore and SQLite persistence. `VisualStateTest` contains explicitly synthetic presentation fixtures; it does not authenticate or execute cloud work. Its profile-menu traversal currently fails on API 37, so the full UI/accessibility suite is not accepted. No authenticated native cloud workflow, live push delivery or physical-phone performance is claimed by these checks.
